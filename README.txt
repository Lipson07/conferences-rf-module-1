КОНФЕРЕНЦИИ.РФ — МОДУЛЬ 1

Автор: Самойлов Артем Сергеевич, 4ИСП9-45
Стек: Python 3, Flask, PostgreSQL, HTML5, CSS3, JavaScript, локальный Bootstrap.

Что реализовано
Регистрация с проверкой всех пяти полей; вход пользователя и администратора;
личный кабинет; создание заявки; просмотр всех заявок; смена статуса;
удаление новой заявки владельцем и любой заявки администратором; отзыв только
после завершения мероприятия. Пароли хранятся в виде хешей.
Форма соответствует Модулю 1: «Создать пользователя», текстовые поля помещения
и даты. Дополнительно выполнены задания этапа 8: участники от 1 до 500,
фильтр администратора по помещению и статусу.

Запуск на Windows
1. Создайте новую пустую базу PostgreSQL с отдельной ролью:
   CREATE USER conf_user WITH PASSWORD 'conf_pass';
   CREATE DATABASE conferences OWNER conf_user;
2. В папке проекта:
   python -m venv venv
   venv\Scripts\activate
   python -m pip install -r requirements.txt
3. Примените схему в новой базе:
   psql -h localhost -U conf_user -d conferences -f schema.sql
4. Создайте администратора:
   python create_admin.py
5. Запустите:
   python app.py
6. Откройте http://127.0.0.1:5000

Запуск в ROSA Linux
После установки Python и PostgreSQL создайте роль и базу как в пункте 1.
В папке проекта:
   python3 -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   psql -h localhost -U conf_user -d conferences -f schema.sql
   python create_admin.py
   python app.py
Если на экзамене нет сети, установите зависимости из выданной папки wheels:
   pip install --no-index --find-links /путь/к/wheels -r requirements.txt
Файлы Bootstrap уже включены и интернет во время работы сайта не нужен.

Настройки
config.py читает переменные PGHOST, PGPORT, PGDATABASE, PGUSER, PGPASSWORD.
По умолчанию: localhost:5432, conferences, conf_user/conf_pass.
Для стабильных сессий при перезапуске задайте SECRET_KEY своей случайной строкой.
Учебные данные администратора из задания: Conf2027 / Demo77.
Не применяйте учебный schema.sql к чужой или рабочей базе.
Скрипт не содержит DROP и не удаляет существующие данные; он не является
системой миграций для уже существующей базы другой структуры.

Файлы
schema.sql — четыре таблицы, ограничения, связи, справочник помещений.
er_diagram.png и er_diagram.mmd — схема той же базы, включая participants.
db.py — соединения и транзакции; repositories.py — классы работы с сущностями.
validators.py — серверная проверка полей и даты.
app.py — маршруты Flask и контроль доступа.
templates — шесть страниц и общий шаблон.
static — стили, валидация, локальный Bootstrap и SVG иллюстрации.
practice — самостоятельные примеры и SQL задания этапов 3–7.
tests/integration.py — повторяемый тест на отдельном тестовом кластере.
TEST_RESULTS.json — результат фактически выполненных проверок.

Проверка
45 интеграционных проверок прошли на PostgreSQL 18.4 и Flask 3.1.3.
Все шесть HTML-снимков страниц просмотрены в браузере при 390×844:
горизонтальное переполнение не обнаружено. Отправка форм проверялась
интеграционно через Flask test client, не через действия в браузере.
Использовался отдельный временный кластер localhost:55446, затем он остановлен.
Исходные пользовательские базы не использовались и не менялись.
Тест создаёт новую базу со случайным именем, поэтому для его запуска нужна роль
с CREATEDB в отдельном тестовом кластере. Тест не удаляет существующие базы.
